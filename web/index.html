음성 녹취·정리

음성은 이 PC에서만 처리하고, 문서 작성 단계에서 녹취록 텍스트만 LLM에 보냅니다.

작업 목록

    녹음 파일을 올리면 대화 흐름과 정리 문서가 여기 나옵니다.
    7분 회의 기준 약 8분 걸립니다 (화자분리가 대부분). 한 명이 말하는 강의·메모는 화자분리를 건너뛰어 훨씬 빠릅니다.

    새 녹음

    녹음 파일을 끌어다 놓거나 클릭해서 선택
    마이크로 바로 녹음합니다. 소리는 이 PC 밖으로 나가지 않습니다.
    알면 꼭 넣어주세요. 화자분리 정확도가 가장 크게 오릅니다.
    화자별 이름 확률을 이 후보 안에서 계산합니다.
    화자·담당자 매핑은 추론형 대형 모델(Claude, GPT-5 급)이 가장 정확합니다. claude-code, codex 는 이 PC에 로그인된 CLI에 넘겨 작성하므로 API 키가 필요 없습니다.

    LLM 설정

    문서 작성, 녹취록 보정, 대화 분석에 쓸 모델과 API 키를 여기서 정합니다. 환경변수나 llm.toml 없이도 동작합니다. 키는 이 PC의 에 나만 읽을 수 있게 저장하고 화면으로 다시 보내지 않습니다. 환경변수나 --env-file 로 이미 넣은 키가 있으면 그쪽이 먼저 쓰입니다. 음성 처리에는 LLM을 쓰지 않습니다.

    기억한 용어

    대화 흐름에서 발화를 고치면 「잘못 인식된 표기 → 올바른 표기」를 녹음 유형별로 기억합니다. 같은 고침이 2번 쌓이거나 직접 고정하면 다음 녹음부터 인식 힌트와 자동 바로잡기에 쓰입니다. 모든 처리는 이 PC 안에서 하고 LLM을 부르지 않습니다. 「공통」은 모든 유형에 적용됩니다.

    VOICEKIT_MEMORY=off 라서 기억한 용어를 쓰지 않습니다.

    에이전트 연결

    Claude Code, Codex 같은 에이전트가 이 PC에서 음성 인식·화자분리를 직접 실행하게 연결합니다. 음성은 로컬에서만 처리되고, 에이전트는 녹취록 텍스트를 읽어 자기 모델로 문서를 씁니다. 연결하면 이 화면의 작업 폴더를 에이전트와 공유하므로, 에이전트가 만든 녹취가 작업 목록에 바로 나타납니다.

    녹음 유형

    유형마다 문서 양식(지시문)과 기본 처리 방식이 다릅니다. 내장 유형을 고쳐 저장하면 사용자 파일()이 내장본을 덮어쓰고, 삭제하면 내장본으로 돌아갑니다.
